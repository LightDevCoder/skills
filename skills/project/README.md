# Project delivery

[简体中文](README.zh-CN.md)

Bootstrap projects, clarify requirements, plan tasks, implement features, publish releases, and review friction.

Categories help you browse related skills; they do not enforce a rigid pipeline. The behavior of each package is defined in its `SKILL.md`.

## User-invoked

- **[project-init](project-init/SKILL.md)** — Set up workspace layout and task tracker settings for a new or existing project so planning and coding start from a shared foundation.
- **[project-clarify](project-clarify/SKILL.md)** — Read existing repository files and ask targeted questions only about remaining open decisions before writing a spec.
- **[project-spec](project-spec/SKILL.md)** — Turn clarified decisions into a technical specification (SPEC) without re-asking settled questions.
- **[project-tickets](project-tickets/SKILL.md)** — Break an approved specification into an ordered list of standalone tasks with clear dependencies, ready for implementation.
- **[implement](implement/SKILL.md)** — Build or update a single well-defined task (code, documentation, or configuration), verify it locally, and hand it off for review.

## Model- or user-invoked

- **[kanban-worker](kanban-worker/SKILL.md)** — Claim and complete a single task from a Light-Kanban board during scheduled runs, picking up feedback and in-progress work first.
- **[release-workflow](release-workflow/SKILL.md)** — Manage project releases through verified checks, document synchronization, git tagging, and GitHub publication.
- **[project-retro](project-retro/SKILL.md)** — Review completed sessions to find friction in project layout, automated checks, instruction clarity, or tool usage, then suggest concrete fixes.
