# v0.2.6 — 更清楚的旅行手册，可选择启用 AI

[English GitHub Release](https://github.com/LightDevCoder/skills/releases/tag/v0.2.6) · [English release notes](RELEASE_NOTES.md) · [发布清单](RELEASE_MANIFEST.zh-CN.md)

本次主要优化 `light-travelpage`：每日安排与路线放在一起，保留提供的旅行和预订资料，并在生成前选择是否启用 AI。集合仍包含 36 个 Skill。

## 主要变化

### 每日安排与地图放在一起

点击日期立即打开当天页面。电脑端地图与安排并排，手机端地图放在安排上方。选择行程或地点列表中的地点会展开整组并高亮该地点，其余地点仍可见。切换日期收起之前的展开，刷新共享记录保留所选日期。日期未定的草稿显示 `DAY n`，也能正常初始化。

路线与行程、预订、账本、to-do 并列。次级栏目只有材料时，顶栏提供直达链接；更多菜单只保留额外栏目。航班、酒店、票据状态与受保护的原始材料均保留。地理轮廓保留来源说明，区分游览顺序与实际道路。

### 各个界面采用同一风格

旅行手册使用纸色、墨色和砖红强调。标题与大日期使用系统衬线字体，控件使用系统界面字体。登录页、地图控件、票据预览、账本表单和可选 AI 面板采用相同配色；地图、费用类别和成员颜色保留各自含义。保留双语显示及未完成的表单草稿。

### 生成前选择是否启用 AI

用户尚未选择时，Skill 在生成新页面前询问是否启用 AI；已有选择就直接沿用，默认关闭。关闭时不生成 AI 入口和客户端。

启用后，通过受鉴权保护的服务端连接使用 Chat Completions 或 Responses 工具调用。可配置已有的本地 CPA 加已授权 Tunnel、已有的海外 CPA，或 API 服务。选择 AI 本身不包括搭建这些服务。

助手可读取行程与预订，并使用已启用的 to-do、票据状态和共同费用操作。原始旅行资料和商家订单保持只读，凭据只留在服务端。界面分别显示已确认的动作和模型文字；保存结果未确认时重试原请求。读取失败保留尚未发送的草稿，浏览器存储异常时仍可打开弹窗查看提示。

## 升级说明

新项目使用手册模板，AI 需选择后才启用。只更新数据时保留原界面、旅程身份、记录 ID 和共享状态。为兼容的现有页面增加 AI 时，按接入说明配置 `provider: openai`、重新构建、设置服务端变量，并在原有指定 D1 数据库执行 `0002_ai_requests.sql`，无需重置数据。

当前 AI 仅接收文字，不包含票据图片理解。服务与模型必须支持所选工具调用协议，不能仅凭“兼容”标签判断。

日期条支持普通鼠标按住拖动，拖动不会误选日期；触控和触控板保留原生横滑。资料校验会在构建前拒绝带前缀的 API 密钥字段及密钥格式。

## 验证范围

本地候选通过 80 项模板测试、4 项生成器测试，以及 AI 关闭、开启和空日期草稿的构建。桌面与 390px 浏览器检查保留 7 天、53 项安排、2 段航班、4 家酒店和 14 份材料。AI 浏览器检查使用本地合成服务，不代表已验证远端模型或实体手机。

集合检查通过 528 项 pytest 测试、156 项 unittest 测试、编译与公开文档检查。候选版本识别使用独立版本目录测试，避免固定上一发布版本号。

用户授权的第 4 轮源码验收已通过，包含独立 Standards/Spec 和另一全新 Evaluator 的全包终检。指定提交 CI、受保护的 annotated tag、标签及最新主干全新安装属于独立的 release-workflow 门禁。发布清单保留发布前快照，已核实的发布事实在发布后记录于 `main`。
